## 1. AI 协同工作流（核心原则）

### 1.1 先说后写，确认后动
* **原则**：AI 在动手写任何核心脚本或功能代码之前，**必须先和用户进行对齐与确认**。
* **优秀 Prompt 示例**：
  > “帮我写一个敌人巡逻脚本。**先列出你打算用的变量名和方法名，我确认后再写代码。**”
* **AI 行为规范**：
  1. 收到功能需求后，先构思类结构。
  2. 列出拟使用的**类名**、**变量名**（包括其数据类型与含义）以及**方法名**（包括入参和返回值类型）。
  3. 等待用户确认。用户提出修改意见后进行调整；用户确认无误（或给予批准）后，AI 才能实际写入/修改文件。

### 1.2 Git 管理：小步快跑，一功能一 Commit
* **原则**：利用 Git 进行精细化版本控制，方便随时无损回滚。
* **AI 行为规范**：
  * 每当在 Unity 中实现并验证完一个独立子功能（例如：完成了 `MapDataStore.cs` 基础定义、完成了 `TerrainLayerGen.cs` 核心生成等），立即执行一次 Git 提交。
  * Commit 提交信息需简洁明了，采用规范的 `feat: ...` 或 `fix: ...` 格式（例如：`feat: create MapDataStore singleton and core structs`）。

### 1.3 代码自审与 Review
* **原则**：写完一段代码后，AI 必须立即进行自我 Review，排查隐患。
* **AI 自审检查问题**：
  > **“这段代码有没有潜在的 bug 或性能问题？”**
* **Review 重点**：
  * **空指针异常 (NullReferenceException)**：引用类型、Unity 组件、未初始化的数组是否做了空值校验或安全兜底？
  * **性能瓶颈**：Update 中是否有高频的 `GetComponent`、`Find`、或者大数组的频繁 GC 内存分配？
  * **逻辑边界**：数组边界是否会越界？除法中除数是否可能为 0？

## 2. 代码命名规范（C# / Unity）

为了保持代码的统一性，所有 C# 代码均采用业界标准的 Unity 命名风格：

| 元素类型 | 命名规则 | 示例 | 备注 |
| :--- | :--- | :--- | :--- |
| **类 (Class) / 接口 (Interface)** | PascalCase | `MapDataStore`, `IClimateController` | 接口以大写 `I` 开头 |
| **结构体 (Struct) / 枚举 (Enum)** | PascalCase | `ResourceData`, `TerrainType` | |
| **公共方法 (Public Method)** | PascalCase | `InitArrays()`, `GetClimateData()` | 动词开头，清晰表达意图 |
| **私有方法 (Private Method)** | PascalCase | `CalculateDangerBias()`, `ApplyFog()` | |
| **公共变量/属性 (Public Variable/Property)** | PascalCase | `CurrentSeed`, `TerrainLayer` | 属性可配合 `{ get; private set; }` |
| **私有/保护字段 (Private/Protected Field)** | camelCase (带下划线) | `_mapSize`, `_staticClimate` | 统一以 `_` 前缀开头，便于区分局部变量 |
| **局部变量 (Local Variable)** | camelCase | `ringDistance`, `noiseValue` | |
| **常量 (Constant)** | ALL_CAPS | `MAP_SIZE`, `CENTER` | 下划线分割单词 |
| **枚举值 (Enum Members)** | ALL_CAPS | `PLAINS`, `MOUNTAIN`, `WATER` | |

## 3. 四层地图系统统一命名定义（首批对齐）

根据地图设计说明书，以下全局核心数据结构的变量名已标准化：

### 3.1 地图核心单例：`MapDataStore`
* 静态单例：`public static MapDataStore Instance;`
* 常量定义：
  * 地图尺寸：`public const int MAP_SIZE = 200;`
  * 地图中心：`public const int CENTER = 100;`
* 数据层数组名：
  * `public TerrainType[,] terrainLayer;`
  * `public ClimateData[,] rawClimateLayer;`
  * `public ResourceData[,] resourceLayer;`
  * `public BuildingData[,] buildingLayer;`
  * `public MonsterFogData[,] monsterFogLayer;`

### 3.2 变量命名速查
* 高度噪声：`rawAltitude`, `finalAltitude`, `altitudeNoiseScale`
* 湿度噪声：`humidity`, `humidityNoiseScale`
* 温度噪声：`temperature`, `temperatureNoiseScale`
* 圈层切比雪夫距离：`ringDistance`
* 圈层系数：`dangerBias`
* 探索状态：`isExplored` (迷雾层)
* 建筑阻挡：`isBuildingBlocked`
